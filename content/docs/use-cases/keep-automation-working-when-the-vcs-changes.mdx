## The scenario

A repository rebases or rewrites Git history, or declares that it now uses
Jujutsu. Automation should react to meaningful observations rather than to
tool output or changed commit hashes. Mori has a normalized observation model,
but its ingest path still selects Git extraction.

## How it works

1. A VCS adapter extracts changesets and refs; Mori records normalized observations for selectors and reactions.
2. Content-hash deduplication recognizes work already observed under a different Git SHA, avoiding duplicate reactions after a replay.
3. Ingest detects an orphaned cursor. An exact replay can resume from the merge base after checking the content index; ambiguous rewrites halt for review.

These Git behaviors are delivered. Two **discovered** features remain: selecting
an adapter from the declared VCS and implementing Jujutsu extraction, and
retaining durable old-to-new rewrite lineage when content changes. Declaring
`Jujutsu` in project metadata does not yet switch the observer.
