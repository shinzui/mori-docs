Commands for working with AI agent roles and launching Claude sessions.
See [Agent Sessions](/docs/guides/agent-sessions) for the full guide on session
types, common behavior, and tool permissions.

## `mori agent list`

List configured agent roles.

```bash
mori agent list
mori agent list --json
```

## `mori agent context`

Generate agent context for a specific role as JSON.

```bash
mori agent context <role>
```

See [Agent Context](/docs/concepts/agent-context) for details.

## `mori agent assist`

Start a Claude session with mori project context.

```bash
mori agent assist
mori agent assist --include-test-deps
mori agent assist --debug
```

Loads the project config, resolves dependencies from the registry, and
launches Claude with a system prompt containing project metadata. The
`--debug` flag prints the prompt instead of starting a session.

`Test`-scoped dependencies (see [Dependency
scope](/docs/schema-guide#dependency-scope)) are excluded from the
resolved-dependency context block and the `Read(path:.../*)` allowed-tools
list by default — pass `--include-test-deps` to opt back in.

## `mori agent bootstrap`

Start a Claude session to bootstrap a new mori project.

```bash
mori agent bootstrap
mori agent bootstrap --namespace shinzui --name my-project
mori agent bootstrap --corpus --upstream owner
mori agent bootstrap --seihou
mori agent bootstrap --debug
```

### Flags

| Flag | Description |
|------|-------------|
| `--namespace`, `-n` | Pre-seed the project namespace |
| `--name` | Pre-seed the project name |
| `--corpus` | Bootstrap a corpus project (wraps third-party repos as git subtrees); adds `Bash(just *)` to the session allow-list |
| `--upstream`, `-u` | Pre-seed the upstream GitHub owner (corpus mode) |
| `--seihou` | Bootstrap a project that ships seihou templates; adds the `seihou` CLI to the allow-list and injects template authoring guidance into the system prompt |
| `--debug` | Print the system prompt instead of starting a session |

## `mori agent bootstrap-agent-plan`

Start a Claude session pre-loaded with everything needed to author, register,
and verify a new agent plan end-to-end.

```bash
mori agent bootstrap-agent-plan
mori agent bootstrap-agent-plan \
  --title "Schedule reactions with idempotency checks" \
  --kind exec-plan \
  --summary "EP for scheduled reactions" \
  --description "Add a per-reaction schedule field with optional idempotency check" \
  --depends-on mori://acme/event-store/plans/7-typed-event-encoder
mori agent bootstrap-agent-plan --debug
```

The session's system prompt embeds the rendered agent-plans extension schema,
a snapshot of the project's existing plans, the canonical Markdown skeleton,
and the validate / register / verify workflow. The agent calls
`bun .claude/skills/exec-plan/init-plan.ts` to scaffold the file, fills in
the body, appends an `ExposedPlan` entry to `mori/agent-plans.dhall`, runs
`mori validate` and `mori register --local`, and verifies with
`mori plans show`.

### Flags

| Flag | Description |
|------|-------------|
| `--title` | Pre-seed the plan's title |
| `--kind` | Pre-seed the plan kind: `exec-plan` or `master-plan` |
| `--summary` | Pre-seed the one-line summary used in `mori/agent-plans.dhall` |
| `--description` | Free-form goal description seeded into the agent's first instruction |
| `--depends-on` | `mori://` URI of a plan this one depends on; repeatable |
| `--debug` | Print the system prompt instead of starting a session |

All flags are optional; when omitted, the agent asks once for what is missing
and proceeds.

## Extension bootstrap commands

Start schema-aware Claude sessions for authoring extension entries.

```bash
mori agent bootstrap-cookbook
mori agent bootstrap-tech-radar
mori agent bootstrap-upstream-issues
mori agent bootstrap-checklist
mori agent bootstrap-ddd
mori agent bootstrap-cookbook --debug
```

Each command embeds the extension schema, the pinned mori-schema URL and hash,
the current project snapshot, and the author / validate / register / verify
workflow. The commands refuse to launch when `mori.dhall` or the extension file
is pinned to a different schema commit than the running binary; migrate first
with `mori schema migrate --apply` or `mori schema migrate --apply --file
mori/<extension>.dhall`.

See [Extension Bootstrap](/docs/guides/bootstrap-extensions) for the shared
workflow and staleness guard.

## `mori agent schema-migrate`

Start a Claude session to migrate and fix `mori.dhall` schema.

```bash
mori agent schema-migrate
mori agent schema-migrate --file path/to/mori.dhall
mori agent schema-migrate --debug
```

### Flags

| Flag | Description |
|------|-------------|
| `--file` | Target file to migrate (default: `mori.dhall`) |
| `--debug` | Print the system prompt instead of starting a session |

## `mori agent claude`

Start a Claude session with full project context, skills, and subagents.

```bash
mori agent claude
mori agent claude --include-test-deps
mori agent claude --debug
```

Loads project config, resolves dependencies, and launches Claude with:
- Project metadata (name, language, type, packages, docs)
- Resolved dependency context with local paths
- Cookbook catalog entries (if `mori/cookbook.dhall` exists)
- Skills and subagents from `~/.config/mori/agents/` and `.mori/agents/`
- Context caching for faster subsequent launches

`Test`-scoped dependencies are excluded by default. See [`mori agent
assist`](#mori-agent-assist) for details.

### Flags

| Flag | Description |
|------|-------------|
| `--include-test-deps` | Include `Test`-scoped dependencies in the resolved-deps context block and `Read(path:.../*)` allowed-tools |
| `--debug` | Print the system prompt and cache state instead of starting a session |

## `mori agent ask`

Start a Claude session about another project registered in the local registry.

```bash
mori agent ask shinzui/mori
mori agent ask
mori agent ask shinzui/mori --package mori-core
mori agent ask shinzui/mori --debug
mori agent ask shinzui/mori --no-cd
mori agent ask shinzui/mori --include-test-deps
```

Omit the project argument to pick interactively. A bare project name must be
unambiguous; otherwise use `namespace/name`. See [Agent Ask](/docs/guides/agent-ask)
for the workflow details.

## `mori agent automate`

Start a Claude session specialized for automation config authoring and debugging.

```bash
mori agent automate
mori agent automate --debug
```

Provides context about the automation system including event selectors, reaction
types, trailer matching, and event-data interpolation. Useful for creating or
troubleshooting `mori.automation.dhall` configurations.

### Flags

| Flag | Description |
|------|-------------|
| `--debug` | Print the system prompt instead of starting a session |

## `mori agent exec`

Run a prompt or skill against every repo in a [group](/docs/guides/registry-groups),
one Claude session per repo. Each run is recorded as a session and recalls
accumulated memory, so later repos can build on what earlier repos learned. See
[Agent Exec](/docs/guides/agent-exec) for the workflow.

```bash
mori agent exec --group backends --prompt "Upgrade the pinned GHC to 9.10"
mori agent exec --group backends --skill upgrade-deps
mori agent exec --group backends --filter "shinzui/*" --dry-run
mori agent exec --group backends --prompt "..." --follow-up
mori agent exec --group backends --prompt "..." --debug
```

Supply exactly one of `--prompt`/`-p` or `--skill`. Runs are sequential by
default so later repos can see memory written by earlier ones.

### Flags

| Flag | Description |
|------|-------------|
| `--group GROUP` | Run across the repos in GROUP (required) |
| `--prompt`, `-p TEXT` | Instruction to run in each repo |
| `--skill NAME` | Claude Code skill to run in each repo |
| `--filter GLOB` | Restrict to `<namespace>/<name>` matching GLOB |
| `--jobs`, `-j N` | Parallel repos (default 1; values > 1 are reserved and disable accumulate-as-you-go) |
| `--fail-fast` | Stop after the first repo that fails |
| `--dry-run` | List the repos without running |
| `--follow-up` | Recall the prior run's session and memories |
| `--debug` | Print the assembled prompt instead of launching Claude |

## `mori agent memory`

Record or list reusable agent memory for a [group](/docs/guides/registry-groups)
or a single repo. `mori agent exec` recalls active memory into each session's
prompt and writes new memory back; you can also manage it directly.

### `mori agent memory record`

```bash
mori agent memory record --group backends "Use just build, not cabal directly"
mori agent memory record --repo <project-id> "Migrations live in db/migrate" --type pattern --tag db
```

Pass exactly one scope: `--group GROUP` (a mori group name) or `--repo
PROJECT_ID` (a mori project id). The memory text is a positional argument.

| Flag | Description |
|------|-------------|
| `--group GROUP` | Scope the memory to a mori group |
| `--repo PROJECT_ID` | Scope the memory to a single project |
| `--type TYPE` | Memory type: `fact` (default), `pattern`, `preference`, `constraint`, or `instruction` |
| `--tag TAG` | Tag to attach to the memory; repeatable |

### `mori agent memory list`

```bash
mori agent memory list --group backends
mori agent memory list --repo <project-id> --type pattern
```

Lists active memory for the given scope. Pass `--group` or `--repo` (as above);
`--type TYPE` filters to a single memory type.
