Commands for VCS event ingestion and reactive automation.

See [Automation Configuration](/docs/concepts/automation-configuration) for the automation layer design.

## `mori automate ingest`

Ingest VCS events into the local event store.

```bash
mori automate ingest git
mori automate ingest --repo /path/to/repo --vcs git
```

### Behavior

- Scans VCS history for new events
- Normalizes to canonical event format
- Appends to local event store
- Updates cursor position

## `mori automate run`

Run single-repo automation (ingest + subscriptions).

```bash
mori automate run
mori automate run --config path/to/config.dhall
mori automate run --path /path/to/repo
mori automate run --register
```

### Behavior

- Loads automation config from disk
- Ingests VCS events, then runs all subscriptions concurrently
- Matches events against selectors, triggers and executes reactions

### Flags

| Flag | Description |
|------|-------------|
| `--config`, `-c` | Path to automation config (default: `mori.automation.dhall`) |
| `--path` | Repository path (default: current directory) |
| `--register` | Also register with the daemon via event store |

## `mori automate daemon`

Run multi-repo automation daemon.

```bash
mori automate daemon
```

### Behavior

- Bootstraps config registry from `automation_registrations` projection
- Subscribes to `automationRegistration` category for live config updates
- Routes repository events to registered repos' automation configs
- Concurrent subscription workers (automation, executor, registry, workflow, registration)
- Fully event-driven — no filesystem polling

See [Automation Daemon](/docs/guides/automation-daemon) for details.

## `mori automate register`

Register the current repo's automation config with the daemon.

```bash
mori automate register
mori automate register --config path/to/config.dhall
mori automate register --path /path/to/repo
```

### Behavior

- Loads and validates automation config
- Writes `AutomationRegistered` event to the event store
- Idempotent — registering twice is a no-op

## `mori automate deregister`

Remove automation registration for a repo.

```bash
mori automate deregister
mori automate deregister --path /path/to/repo
```

### Behavior

- Writes `AutomationDeregistered` event
- Daemon stops processing events for this repo
- Idempotent — deregistering an unregistered repo is a no-op

## `mori automate update`

Update a registered automation config after editing the config file.

```bash
mori automate update
mori automate update --config path/to/config.dhall
```

### Behavior

- Re-reads config from disk, computes new hash
- Writes `AutomationConfigUpdated` event if hash differs
- Daemon picks up changes live (no restart needed)
- Idempotent — updating with same config is a no-op

## `mori automate list`

List all registered automation configs.

```bash
mori automate list
mori automate list --json
```

## `mori automate migrate`

One-time migration: discover all projects with automation configs and register them.

```bash
mori automate migrate
```

### Behavior

- Scans all registered projects for `mori.automation.dhall`
- Registers each discovered config via the event store
- Idempotent — safe to run multiple times

## `mori automate inspect`

Inspect automation configuration.

```bash
mori automate inspect
mori automate inspect --json
```

### Output

- Automation config status and hash
- Execution policy (local/CI)
- Registered event selectors

## `mori automate explain`

Explain why a reaction did or did not run for a specific event.

```bash
mori automate explain <global-position>
mori automate explain <global-position> --config path/to/config.dhall
mori automate explain <global-position> --json
```

### Flags

| Flag | Description |
|------|-------------|
| `--config`, `-c` | Path to automation config |
| `--json` | JSON output |

## `mori automate generate`

Generate automation config templates.

```bash
mori automate generate <template>
mori automate generate <template> --output path/to/output.dhall
```
