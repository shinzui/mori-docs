Render evaluated Mori metadata.

```bash
mori show
mori show --json
mori show --full
mori show --full --json
```

Displays the fully evaluated Mori configuration for the current project.

## Flags

| Flag | Description |
|------|-------------|
| `--json` | Output as JSON |
| `--full` | Display detailed information for all sections (repos, packages, bundles, dependencies, APIs, agents, skills, subagents, standards, docs) |

## Canonical refs in output

`mori show --full` and `mori show --json` print a [canonical
`mori://` ref](/docs/concepts/canonical-refs) for every artifact owned by the
project — docs, packages, repos, skills, subagents, APIs, cookbook entries,
and seihou templates.

In text mode, the ref appears on a dim line beneath each artifact. In JSON
mode, every artifact object carries a `canonicalRef` field:

```bash
mori show --json | jq '.docs[].canonicalRef'
mori show --json | jq '.packages[].canonicalRef'
```

Doc references in JSON use flattened string fields for easier downstream
processing: `kind`, `audience`, `location`, and `locationType`.

## Lifecycle and deprecation

`mori show --full` prints the project's lifecycle and, when present, its
`Alternative` / `Details` [deprecation
guidance](/docs/guides/schema-reference#deprecation). Each package prints its
own lifecycle; a package with no override shows the project's lifecycle marked
`(inherited)`, followed by any package-specific guidance (which is never
inherited).

The same convention is used by [`mori registry show --full`](/docs/commands/registry#mori-registry-show)
and `mori registry show --json`.
