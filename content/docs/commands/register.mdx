Register the current project in the local registry.

```bash
mori register
mori register --local
mori register --dir /path/to/project
mori register --no-seihou-discovery
```

## Behavior

- Loads and validates `mori.dhall`
- Queries the extension catalog and loads any `mori/<extension>.dhall` files for active extensions
- Extracts skills and subagents from the config
- Writes `ProjectRegistered` event to the event store (including skills, subagents, and extension data)
- If project already exists, emits granular update events (diffing skills, subagents, and extensions)
- Inline projection populates the read model immediately

## Flags

| Flag | Description |
|------|-------------|
| `--local` | Register in local registry only |
| `--dir` | Project directory (default: current directory) |
| `--no-seihou-discovery` | Skip the auto-discovery probe for seihou template manifests. Use when the project root holds a `module.dhall` that isn't a seihou module instance (e.g. a seihou type definition file) and the probe produces a noisy "Missing record field" warning every run |

Internal callers (`mori observe`, `mori automate register`, `mori registry
reregister`) always run the discovery probe — `--no-seihou-discovery` only
applies to direct invocations of `mori register`.
