`mori status` prints a single health report for the mori project in the current
directory.

```bash
mori status
mori status --json
```

## Report Sections

| Section | What it checks |
|---------|----------------|
| Header | Project identity and overall verdict |
| Schema | `mori.dhall`, known extension configs, and automation schema pins |
| Registry | Whether `(namespace, name)` exists in the read model |
| Observation | Whether the project is linked with `mori/repo-id` and has current observation state |
| Automation execution | Whether any reaction execution leg is stuck or has an open halt |

Schema files can be `current`, `stale`, `unpinned`, or `missing`. `unpinned`
means the file uses a local import, which is expected in dogfooding setups and
is not treated as an error.

The automation-execution line reports `ok` when no leg is stuck or halted. When
it is unhealthy it shows how many legs are affected, degrades the verdict to
`attention`, and adds an issue pointing at
[`mori doctor --reactions`](/docs/commands/doctor#--reactions).

## Exit Codes

| Code | Meaning |
|------|---------|
| `0` | Healthy |
| `1` | Attention needed: stale pin, missing or empty registered automation source, not registered, not observed, automation config not observed, or unhealthy automation execution |
| `2` | `mori.dhall` is missing or unparseable |

Use `--json` in scripts or CI:

```bash
mori status --json | jq '.verdict'
mori status --json | jq '.issues'
mori status --json | jq '.automationExecution'
mori status --json | jq '.schema.automations'
```

`automationExecution` carries `{"healthy": true|false, "unhealthyLegs": 0}`.

Automation pins are reported in `schema.automations`, keyed by automation name.
Each entry has `config_path`, `origin`, `problem`, and `files`. Active registrations
are authoritative; the conventional config is used only when none exist. A missing
registered path or empty directory needs attention and never falls back to another
config. This replaces the former `schema["mori.automation.dhall"]` JSON field.

See [Status](/docs/guides/status) for the JSON shape and remediation guidance.


Registration freshness appears in the `registration` JSON object. Use `mori registry freshness --stale-only` for a fleet query; see [Registry Refresh](/docs/guides/registry-refresh).
