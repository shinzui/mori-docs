`mori.dhall` is a `Schema.Project::{ ... }` record describing project identity,
repositories, packages, dependencies, docs, templates, and knowledge bundles.
Use the `::` form so schema defaults fill in optional fields:

```dhall
let Schema = ./schema/package.dhall

in  Schema.Project::{
    , project = Schema.ProjectIdentity::{
      , name = "my-project"
      , namespace = "myorg"
      , type = Schema.PackageType.Application
      , language = Schema.Language.Haskell
      , lifecycle = Schema.Lifecycle.Active
      }
    }
```

## Top-Level Fields

| Field | Type | Purpose |
|-------|------|---------|
| `project` | `ProjectIdentity` | Required project identity |
| `repos` | `List Repo` | Repository references |
| `packages` | `List Package` | Buildable units in the project |
| `bundles` | `List PackageBundle` | Package groups used together |
| `dependencies` | `List Text` | External project dependencies by name |
| `apis` | `List Api` | API definitions |
| `agents` | `List AgentHint` | Agent role hints |
| `skills` | `List Skill` | Agent skill definitions |
| `subagents` | `List Subagent` | Specialized assistant definitions |
| `standards` | `List Text` | Standards this project follows |
| `docs` | `List DocRef` | Documentation references |
| `templates` | `List SeihouTemplate` | Seihou scaffold templates |
| `okfBundles` | `List OkfBundle` | OKF knowledge bundles owned by the project |

Defaulted list fields can be omitted when empty. The schema bundle supplies the
empty lists.

## Deprecation Guidance

`Deprecation` groups an optional replacement with optional migration details:

```dhall
, project = Schema.ProjectIdentity::{
  , name = "my-project"
  , namespace = "myorg"
  , type = Schema.PackageType.Application
  , language = Schema.Language.Haskell
  , lifecycle = Schema.Lifecycle.Deprecated
  , deprecation = Some Schema.Deprecation::{
    , alternative = Some "mori://myorg/my-project-next"
    , details = Some "Move new integrations to my-project-next."
    }
  }
```

Attach it to a project or package only when that item's effective lifecycle is
`Deprecated`. `Maintenance` is a supported state and takes no `deprecation`
record — a maintained project is still the right thing to depend on, so it has
no replacement to name. At least one field must contain non-whitespace text. A package
with `lifecycle = None Schema.Lifecycle` inherits the project lifecycle, but its
deprecation record is always package-specific and is never inherited.
Alternatives are free-form text, so external package coordinates and URLs are
allowed; prefer a canonical `mori://` reference for registered replacements.

## OKF Bundles

Declare OKF knowledge bundles with `okfBundles`, not `bundles`:

```dhall
, okfBundles =
  [ Schema.OkfBundle::{
    , name = "team-knowledge"
    , path = "knowledge/team"
    , profile = Some "https://raw.githubusercontent.com/shinzui/okf-profiles/main/profiles/team.dhall"
    , okfVersion = "0.2"
    , description = Some "Shared team knowledge bundle"
    }
  ]
```

Registration catalogs each bundle and indexes its concepts and links, so they
become searchable across projects and addressable as
`mori://<namespace>/<project>/okf/<bundle>`. A declared `profile` adds advisory
validation that never fails registration.

```bash
mori registry bundles my-project
mori registry concepts my-project
mori registry concepts --search <term>
```

See [OKF Bundles](/docs/guides/okf) for the full picture.
