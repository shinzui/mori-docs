This is the field-by-field reference for `mori.dhall`, the project manifest that
defines a Mori project's identity, packages, dependencies, and agent
configuration.

All Dhall schema files live in the `schema/` directory. The convenience module
`schema/package.dhall` re-exports every type for use in config files:

```haskell
let Schema = ./schema/package.dhall

in  { project = { ... }
    , repos = [ ... ]
    , packages = [ ... ]
    -- etc.
    }
```

## Root Fields

The root type is defined in `schema/Project.dhall`:

| Field | Type | Purpose |
|-------|------|---------|
| `project` | Record | Project identity (name, namespace, type, etc.) |
| `repos` | `List Repo` | Repository references |
| `packages` | `List Package` | Buildable units within the project |
| `bundles` | `List PackageBundle` | Package groupings |
| `dependencies` | `List Text` | Project-level dependency names, resolved via the registry |
| `apis` | `List Api` | API definitions |
| `agents` | `List AgentHint` | AI agent role configuration |
| `skills` | `List Skill` | Agent skill definitions |
| `subagents` | `List Subagent` | Specialized AI assistant definitions |
| `standards` | `List Text` | Names of standard projects this project follows |
| `docs` | `List DocRef` | Project-level documentation |
| `templates` | `List SeihouTemplate` | Seihou scaffold templates shipped by this project |
| `okfBundles` | `List OkfBundle` | OKF knowledge bundles owned by this project |

## project

Project identity. The `(namespace, name)` pair forms the unique registry key.

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | Project name, unique within namespace |
| `namespace` | `Text` | Organization namespace (e.g., `"acme"`) |
| `type` | `PackageType` | Primary project type |
| `description` | `Optional Text` | Brief description |
| `language` | `Language` | Primary language |
| `lifecycle` | `Lifecycle` | Project lifecycle stage |
| `domains` | `List Text` | Domain tags (e.g., `"Billing"`, `"Platform"`) |
| `owners` | `List Text` | Team or individual owners |
| `origin` | `Origin` | Ownership classification (`Own`, `ThirdParty`, `Fork`, `Vendored`) |

```haskell
{ name = "payment-service"
, namespace = "acme"
, type = Schema.PackageType.Application
, description = Some "Handles payment processing"
, language = Schema.Language.Haskell
, lifecycle = Schema.Lifecycle.Active
, domains = [ "Billing", "Platform" ]
, owners = [ "team-payments" ]
, origin = Schema.Origin.Own
}
```

## repos

Repository references. Multiple repos are supported for monorepo-style projects.

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | Logical repo name |
| `github` | `Optional Text` | GitHub path (`"owner/repo"`) |
| `gitlab` | `Optional Text` | GitLab path |
| `git` | `Optional Text` | Generic git URL |
| `localPath` | `Optional Text` | Local filesystem path |

```haskell
[ { name = "main"
  , github = Some "acme/payment-service"
  , gitlab = None Text
  , git = None Text
  , localPath = None Text
  }
]
```

## packages

Buildable units within the project. Each package has its own type, language,
dependencies, and configuration.

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | Package name |
| `type` | `PackageType` | Package classification |
| `language` | `Language` | Primary language |
| `path` | `Optional Text` | Path relative to project root |
| `description` | `Optional Text` | Brief description |
| `visibility` | `Visibility` | Access scope |
| `runtime` | `Runtime` | Runtime characteristics |
| `lifecycle` | `Lifecycle` | Package lifecycle stage (`Active`, `Experimental`, `Deprecated`, `Archived`) |
| `runtimeEnvironment` | `Optional RuntimeEnvironment` | Runtime execution environment |
| `apiSource` | `Optional ApiSource` | API source for Client-type packages |
| `dependencies` | `List Dependency` | Package-level dependencies |
| `docs` | `List DocRef` | Package-specific documentation |
| `config` | `List ConfigItem` | Configuration requirements |

```haskell
[ { name = "payments-core"
  , type = Schema.PackageType.Library
  , language = Schema.Language.Haskell
  , path = Some "payments-core"
  , description = Some "Core payment logic"
  , visibility = Schema.Visibility.Internal
  , runtime = { deployable = False, exposesApi = False }
  , dependencies =
    [ Schema.Dependency.ByName "effectful"
    , Schema.Dependency.ByName "aeson"
    ]
  , docs = [] : List Schema.DocRef
  , config = [] : List Schema.ConfigItem
  }
]
```

### Runtime

| Field | Type | Notes |
|-------|------|-------|
| `deployable` | `Bool` | Produces a deployable artifact |
| `exposesApi` | `Bool` | Exposes an API |

### ApiSource

Declares which API a Client-type package was generated from. The `project`
field must appear in the project-level `dependencies` list — `mori validate`
enforces this invariant.

| Field | Type | Notes |
|-------|------|-------|
| `project` | `Text` | Qualified project name (e.g., `"tan/mls-service-v2"`) |
| `api` | `Optional Text` | API name within source project (for multi-API projects) |
| `specPath` | `Optional Text` | Path to spec file in source project |

```haskell
{ apiSource = Some
    { project = "tan/mls-service-v2"
    , api = None Text
    , specPath = Some "openapi.json"
    }
}
```

Displayed in `mori show --full` and `mori registry show --full`.

### Dependency

Package-level dependencies use a union type with two variants:

**Simple form** — resolve by name via the registry:

```haskell
Schema.Dependency.ByName "effectful"
```

**Augmented form** — attach extra docs, mark scope, or override a path:

```haskell
Schema.Dependency.WithAugmentation
  { name = "hasql"
  , kind = None Schema.DependencyKind
  , source = None Schema.DependencySource
  , scope = Some Schema.DependencyScope.Regular
  , extraDocs =
    [ { key = "hasql-patterns"
      , kind = Schema.DocKind.Cookbook
      , audience = Schema.DocAudience.Internal
      , description = Some "Our hasql usage patterns"
      , location = Schema.DocLocation.LocalFile "docs/hasql-patterns.md"
      }
    ]
  , localPathOverride = None Text
  }
```

The `WithAugmentation` arm requires a flat record literal with all six
fields — there is no `Aug::{ … }` completion helper for this union arm.

### DependencyScope

```
Regular | Dev | Test | Build
```

Optional per-package field. Omitted or `None` means `Regular`. See
[Dependency scope](/docs/schema-guide#dependency-scope) in the schema guide.

### ConfigItem

Declares a configuration requirement for a package.

| Field | Type | Notes |
|-------|------|-------|
| `key` | `Text` | Configuration key name |
| `type` | `ConfigValueType` | Expected value type |
| `required` | `Bool` | Whether the config is required |
| `description` | `Optional Text` | Human-readable description |
| `sourceHint` | `Optional ConfigSourceHint` | Hint for where to find the value |
| `example` | `Optional Text` | Example value |

```haskell
{ key = "DATABASE_URL"
, type = Schema.ConfigValueType.Url
, required = True
, description = Some "PostgreSQL connection string"
, sourceHint = Some (Schema.ConfigSourceHint.EnvVar "DATABASE_URL")
, example = Some "postgres://localhost:5432/payments"
}
```

## bundles

Package groupings for wrapper projects. When an agent resolves a dependency that
matches a bundle name, only the bundle's packages are included.

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | Bundle name (used in dependency resolution) |
| `description` | `Optional Text` | What this bundle provides |
| `packages` | `List Text` | Package names in the bundle |
| `primary` | `Text` | The main package for imports |

```haskell
[ { name = "streamly"
  , description = Some "Streaming data processing"
  , packages = [ "streamly", "streamly-core" ]
  , primary = "streamly"
  }
]
```

## okfBundles

OKF bundles describe directories of Markdown knowledge concepts owned by this
project. They are distinct from `PackageBundle`: package bundles group code
packages for dependency resolution, while OKF bundles expose structured
knowledge through registry commands and canonical refs.

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | Bundle name, unique within the project |
| `path` | `Text` | Project-relative directory containing the bundle |
| `profile` | `Optional Text` | URL or path to the OKF profile the bundle should follow |
| `okfVersion` | `Text` | OKF format version, such as `"0.1"` |
| `description` | `Optional Text` | Human-readable description |

```haskell
[ Schema.OkfBundle::{
  , name = "team-knowledge"
  , path = "knowledge/team"
  , profile = Some "https://raw.githubusercontent.com/shinzui/okf-profiles/main/profiles/team.dhall"
  , okfVersion = "0.1"
  , description = Some "Shared team knowledge bundle"
  }
]
```

## dependencies

Project-level dependency names, resolved by name via the local registry. For
fine-grained control, declare dependencies at the package level using the
`Dependency` union type instead.

```haskell
dependencies = [ "effectful", "aeson", "hasql" ]
```

## apis

API definitions for services that expose APIs.

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | API name |
| `type` | `ApiType` | Specification type |
| `specPath` | `Text` | Path to the API spec file |
| `owner` | `Text` | Package name that owns this API |
| `dependencies` | `List ApiDependency` | Packages that depend on this API |
| `updatePolicy` | `Optional ApiUpdatePolicy` | Update propagation policy |

```haskell
[ { name = "payments-api"
  , type = Schema.ApiType.OpenAPI
  , specPath = "api/openapi.yaml"
  , owner = "payments-service"
  , dependencies =
    [ { package = "payments-client", role = Schema.ApiDependencyRole.Client }
    , { package = "billing-service", role = Schema.ApiDependencyRole.Consumer }
    ]
  , updatePolicy = Some
      { strategy = Schema.ApiUpdateStrategy.ClientFirst
      , allowBreaking = False
      , requireTests = True
      , consumerBatching = Schema.ConsumerBatching.Sequential
      , notes = None Text
      }
  }
]
```

### ApiDependency

| Field | Type | Notes |
|-------|------|-------|
| `package` | `Text` | Package name |
| `role` | `ApiDependencyRole` | `Client` or `Consumer` |

### ApiUpdatePolicy

| Field | Type | Notes |
|-------|------|-------|
| `strategy` | `ApiUpdateStrategy` | `ClientFirst`, `ManualApproval`, or `NoAutomation` |
| `allowBreaking` | `Bool` | Whether breaking changes are allowed |
| `requireTests` | `Bool` | Whether tests must pass before propagating |
| `consumerBatching` | `ConsumerBatching` | `Sequential` or `Parallel` |
| `notes` | `Optional Text` | Additional policy notes |

## agents

Hints for AI coding agents. See [Agent Context](/docs/concepts/agent-context) for full
usage details.

| Field | Type | Notes |
|-------|------|-------|
| `role` | `Text` | Unique role identifier |
| `description` | `Optional Text` | What this role is for |
| `includePaths` | `List Text` | Paths the agent should focus on |
| `excludePaths` | `List Text` | Paths the agent should ignore |
| `relatedPackages` | `List Text` | Package names relevant to this role |

```haskell
[ { role = "backend"
  , description = Some "Backend development agent"
  , includePaths = [ "src/", "lib/" ]
  , excludePaths = [ "dist-newstyle/" ]
  , relatedPackages = [ "payments-core", "payments-service" ]
  }
]
```

## skills

Agent skill definitions following the [agentskills.io](https://agentskills.io) spec.

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | Skill identifier |
| `description` | `Text` | What the skill does |
| `path` | `Optional Text` | Relative path to skill directory |
| `tools` | `List SkillTool` | Tools with language annotations |
| `compatibility` | `Optional Text` | Environment requirements |
| `metadata` | `List { mapKey, mapValue : Text }` | Arbitrary key-value pairs |

```haskell
[ { name = "code-review"
  , description = "Run code review checks"
  , path = Some ".claude/skills/code-review"
  , tools =
    [ { name = "eslint-runner"
      , description = Some "Runs ESLint"
      , languages = [ Schema.Language.TypeScript ]
      }
    ]
  , compatibility = Some "Requires node 18+"
  , metadata = [ { mapKey = "author", mapValue = "platform-team" } ]
  }
]
```

### SkillTool

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | Tool identifier |
| `description` | `Optional Text` | What the tool does |
| `languages` | `List Language` | Languages the tool's scripts use |

## subagents

Specialized AI assistant definitions.

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | Unique identifier (lowercase + hyphens) |
| `description` | `Text` | When to delegate to this subagent |
| `provider` | `Optional Text` | Agent platform (e.g., `"claude-code"`) |
| `model` | `Optional Text` | Model name (e.g., `"sonnet"`, `"gpt-4o"`) |
| `tools` | `List Text` | Tool allowlist |
| `disallowedTools` | `List Text` | Tools to deny |
| `permissionMode` | `Optional PermissionMode` | Permission prompt handling |
| `skills` | `List Text` | Skill names to preload |
| `background` | `Bool` | Always run in background |
| `isolation` | `Optional Text` | Isolation mode (e.g., `"worktree"`) |

```haskell
[ { name = "code-reviewer"
  , description = "Review pull requests for quality"
  , provider = Some "claude-code"
  , model = Some "sonnet"
  , tools = [ "Read", "Grep", "Bash" ]
  , disallowedTools = [] : List Text
  , permissionMode = Some Schema.PermissionMode.AcceptEdits
  , skills = [ "code-review" ]
  , background = False
  , isolation = None Text
  }
]
```

## docs

Project-level documentation references.

| Field | Type | Notes |
|-------|------|-------|
| `key` | `Text` | Unique identifier |
| `kind` | `DocKind` | Documentation classification |
| `audience` | `DocAudience` | Target audience |
| `description` | `Optional Text` | Brief description |
| `location` | `DocLocation` | Where the doc is located |

```haskell
[ { key = "architecture"
  , kind = Schema.DocKind.Guide
  , audience = Schema.DocAudience.Internal
  , description = Some "System architecture overview"
  , location = Schema.DocLocation.LocalFile "docs/architecture.md"
  }
, { key = "db-patterns"
  , kind = Schema.DocKind.Cookbook
  , audience = Schema.DocAudience.Module
  , description = Some "Database access patterns"
  , location = Schema.DocLocation.LocalDir "docs/cookbooks/"
  }
]
```

Docs with `kind = Cookbook` are included in the `cookbooks` field of the agent
context output.

### DocLocation

```
LocalFile <path> | LocalDir <path> | RepoPath <path> | Url <url>
| Canonical <mori://uri>
```

The `Canonical` arm carries a [canonical `mori://`
ref](/docs/concepts/canonical-refs) to another project's artifact. Validated
by the resolver and the registry projection at register time; checked in
bulk by `mori validate --check-refs`.

### MoriArtifactKind

```
Doc | Package | Repo | Skill | Subagent | Api | Cookbook | Template
```

Eight pinned kinds used by the canonical-ref system. URI segments are
plural (`docs`, `packages`, `repos`, `skills`, `subagents`, `apis`,
`templates`) except `cookbook`, which stays singular.

### MoriRef

A record describing a canonical artifact reference:

| Field | Type | Notes |
|-------|------|-------|
| `namespace` | `Text` | Project namespace |
| `name` | `Text` | Project name |
| `kind` | `Optional MoriArtifactKind` | `None` for the project root |
| `key` | `Optional Text` | Artifact key (`None` for `Repo` typically) |
| `anchor` | `Optional Text` | Anchor fragment (e.g., `#section`) |

```dhall
Schema.MoriRef::{
, namespace = "shinzui"
, name = "streamly"
, kind = Some Schema.MoriArtifactKind.Doc
, key = Some "effects-cookbook"
}
```

### EventSelector

Selects which VCS events trigger reactions (used in `mori.automation.dhall`):

```
ChangesetSelector : { name, paths, branches, messagePatterns, trailerPatterns }
RefSelector : { name, refPatterns, kinds }
```

### ReactionAction

Action to execute when a reaction fires:

```
RunCommand : { command, args, workingDir, timeout, env }
EmitEvent : { eventType, streamName, eventData }
Notify : { url, method, headers, bodyTemplate }
Schedule : { delaySeconds, action : ScheduledAction }
```

### ScheduledAction

Non-recursive subset of `ReactionAction` (no `Schedule` variant):

```
RunCommand | EmitEvent | Notify (same fields as ReactionAction)
```

## Validation Rules

Beyond Dhall type-checking, mori applies semantic validation:

1. **Namespace** — must be non-empty and contain no whitespace
2. **No duplicate package names** — package names must be unique within a project
3. **Non-empty dependencies** — all dependency names must be non-empty strings
4. **Bundle integrity** — bundle `primary` must be listed in `packages`; all
   package references must be non-empty

Validate your config with:

```bash
mori validate
```

```haskell
let Schema = ./schema/package.dhall

in  { project =
      { name = "payment-service"
      , namespace = "acme"
      , type = Schema.PackageType.Application
      , description = Some "Handles payment processing"
      , language = Schema.Language.Haskell
      , lifecycle = Schema.Lifecycle.Active
      , domains = [ "Billing", "Platform" ]
      , owners = [ "team-payments" ]
      , origin = Schema.Origin.Own
      }
    , repos =
      [ { name = "main"
        , github = Some "acme/payment-service"
        , gitlab = None Text
        , git = None Text
        , localPath = None Text
        }
      ]
    , packages =
      [ { name = "payments-core"
        , type = Schema.PackageType.Library
        , language = Schema.Language.Haskell
        , path = Some "payments-core"
        , description = Some "Core payment logic"
        , visibility = Schema.Visibility.Internal
        , runtime = { deployable = False, exposesApi = False }
        , dependencies =
          [ Schema.Dependency.ByName "effectful"
          , Schema.Dependency.ByName "aeson"
          ]
        , docs = [] : List Schema.DocRef
        , config = [] : List Schema.ConfigItem
        }
      , { name = "payments-service"
        , type = Schema.PackageType.Application
        , language = Schema.Language.Haskell
        , path = Some "payments-service"
        , description = Some "Payment API service"
        , visibility = Schema.Visibility.Internal
        , runtime = { deployable = True, exposesApi = True }

          [ Schema.Dependency.ByName "payments-core" ]
```
