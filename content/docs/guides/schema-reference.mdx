This is the field-by-field reference for `mori.dhall`, the project manifest that defines a Mori project's identity, packages, dependencies, and agent configuration. All types are defined in the `mori-schema` package and re-exported through `package.dhall`.

## Root Fields

| Field | Type | Purpose |
|-------|------|---------|
| `project` | Record | Project identity (name, namespace, type, etc.) |
| `repos` | `List Repo` | Repository references |
| `packages` | `List Package` | Buildable units within the project |
| `bundles` | `List PackageBundle` | Package groupings |
| `dependencies` | `List Text` | Project-level dependency names |
| `apis` | `List Api` | API definitions |
| `agents` | `List AgentHint` | AI agent role configuration |
| `standards` | `List Text` | Standard projects this project follows |
| `docs` | `List DocRef` | Project-level documentation |

### Dependency

A union type with two forms.

**Simple form — by name:**

```haskell
Schema.Dependency.ByName "effectful"
```

**Augmented form — with extra docs or path override:**

```haskell
Schema.Dependency.WithAugmentation
  { name = "hasql"
  , extraDocs =
    [ { key = "migration-guide"
      , kind = Schema.DocKind.Guide
      , audience = Schema.DocAudience.Module
      , description = Some "Team migration notes"
      , location = Schema.DocLocation.LocalFile "./docs/hasql-migration.md"
      }
    ]
  , localPathOverride = None Text
  }
```

## bundles

Package bundles group related packages that are typically used together. When a dependency name matches a bundle, Mori resolves all packages in the bundle.

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | Bundle name (used for dependency resolution) |
| `description` | `Optional Text` | Brief description |
| `packages` | `List Text` | Package names included in this bundle |
| `primary` | `Text` | Main package for imports (must be listed in `packages`) |

## StandardProject

Standard projects publish shared documentation and conventions. They are referenced by name in the `standards` field and resolved as registered projects.

| Field | Type | Notes |
|-------|------|-------|
| `name` | `Text` | Standard name |
| `scope` | `StandardScope` | Organizational scope |
| `description` | `Optional Text` | Brief description |
| `repo` | `Repo` | Repository containing the standard |
| `docs` | `List DocRef` | Documentation references |
| `appliesTo` | Record | Which project types and languages this applies to |

The `appliesTo` record contains:

| Field | Type | Notes |
|-------|------|-------|
| `types` | `List PackageType` | Project types this standard applies to |
| `languages` | `List Language` | Languages this standard applies to |

## Validation Rules

Beyond Dhall type-checking, mori applies semantic validation:

1. **Namespace** — must be non-empty and contain no whitespace
2. **No duplicate package names** — package names must be unique within a project
3. **Non-empty dependencies** — all dependency names must be non-empty strings
4. **Bundle integrity** — bundle `primary` must be listed in `packages`
