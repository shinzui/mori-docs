Mori is built in three phases:

| Phase | Focus | Goal |
|-------|-------|------|
| **Phase 1** | Local-First | Fully functional on a single developer machine |
| **Phase 2** | Global Registry | Organization-wide coordination and sync |
| **Phase 3** | Advanced Features | Version pinning, trust policies, cross-repo workflows |

## Phase 1: Local-First

**Goal**: A developer can use Mori entirely locally to:
- Initialize and validate projects
- Register dependencies (wrapper projects)
- Query agent context
- Ingest VCS events and run automation

**Objective**: Core infrastructure that everything else builds on.

## Open Design Questions

### Resolved

| Question | Decision |
|----------|----------|
| Event store | MessageDB on PostgreSQL |
| Local registry storage | PostgreSQL projections (not SQLite) |
| Dependency model | Registry-first resolution |
| ProjectType vs PackageType | Merged into PackageType |
| Repository identity | TypeID generated on `mori init` |
| Project namespace | Required `namespace` field in Project.dhall |
| touchedPaths in ChangesetObserved | Included in payload for path-based matching |
| Project-level dependencies | `List Text` at project root; `List Dependency` (union) at Package level |
| Cookbooks | Modeled as `docs` entries with `kind = Cookbook` |
| ApiUpdatePolicy location | Stays in identity schema (SCHEMA.md) with behavioral note |
| Worker process model | Long-running `mori automate run` with 5 concurrent subscriptions (registry, config-observation, automation, reaction-executor, workflow) |
| Cross-repo communication | Signal-based dispatch with workflow tracking |
| Multi-repo automation | `mori automate daemon` discovers registered repos |

### Still Open

| Question | Notes |
|----------|-------|
| VCS Adapter mechanism | Git hooks? Polling? fswatch? (Phase 1: CLI-driven `mori automate ingest`) |
| Event versioning | Elegant solution in progress |
| Standards distribution | How are org-wide standards versioned and resolved? |

## Success Criteria

### Phase 1 Complete When

- [x] `mori init` creates valid project
- [x] `mori register --local` registers project in local registry
- [x] `mori deps locate` resolves dependencies by name
- [x] `mori agent context` returns structured JSON
- [x] `mori automate ingest git` populates event store
- [x] `mori automate run` executes matching reactions
- [x] `mori automate daemon` runs multi-repo automation
- [x] `mori workflow list/status/trace` provides workflow observability
- [x] `mori reaction list/show` provides reaction observability
- [ ] All commands work offline (no network required)
- [ ] Test coverage > 80% (currently 425 tests passing)
- [ ] Documentation complete

### Phase 2 Complete When

- [ ] Global registry service deployed
- [ ] `mori register` pushes to global registry
- [ ] `mori registry sync` pulls updates
- [ ] CI can enforce registry policies
- [ ] Cross-team dependency resolution works
