The `mori.dhall` schema defines the **identity layer** of Mori configuration. It is schema-first (Dhall), graph-oriented (repos, packages, APIs, consumers), and identity-focused (what a project *is*, not what *happens*).

## Design Principles

1. **Single source of truth** — Dhall files are authoritative; JSON is derived
2. **Typed, composable metadata** — no stringly-typed conventions
3. **CLI-first UX** — humans interact via `mori` commands, not raw Dhall
4. **Agent-aware by default** — metadata designed to generate reliable agent context
5. **Knowledge lives where it is owned** — shared knowledge in shared projects
6. **Identity precedes behavior** — `mori.dhall` describes what a project *is*


## Root Type: Project

The `Project` type defines the shape of every `mori.dhall` file:

```haskell
{ project :
    { name : Text
    , namespace : Text
    , type : PackageType
    , description : Optional Text
    , language : Language
    , lifecycle : Lifecycle
    , domains : List Text
    , owners : List Text
    }
, repos : List Repo
, packages : List Package
, bundles : List PackageBundle
, dependencies : List Text
, apis : List Api
, agents : List AgentHint
, standards : List Text
, docs : List DocRef
}
```

## Dependency Model

Dependencies use a **registry-first** model with two forms:

```haskell
-- Dependency.dhall
< ByName : Text
| WithAugmentation :
    { name : Text
    , extraDocs : List DocRef
    , localPathOverride : Optional Text
    }
>
```

Additional types classify dependencies:

```haskell
-- DependencyKind.dhall
< Internal | ThirdParty >

-- DependencySource.dhall
< Hackage | Npm | PyPI | Crates | Maven
| GitHub | GitLab | Git | Local | Other : Text >
```

### Resolution Rules

1. **Extract dependency name** from declaration
2. **Query local registry** for name
3. **If found**: return filesystem path, load project's `mori.dhall` as authoritative
4. **Else query global registry** (if online)
5. **Else check `localPathOverride`** (fallback for unregistered deps)
6. **Else**: treat as unannotated, warn user

Key principles: registry-first lookup, single authority per dependency, consumers augment but never redefine, deterministic resolution, offline-capable.

## Documentation Model

Documentation references attach structured knowledge to projects, packages, and dependencies:

```haskell
-- DocRef
{ key : Text
, kind : DocKind
, audience : DocAudience
, description : Optional Text
, location : DocLocation
}

-- DocKind.dhall
< Reference | Guide | Cookbook | Spec | Runbook | Notes | Other : Text >

-- DocAudience.dhall
< Module | User | API | Internal | Other : Text >

-- DocLocation.dhall
< LocalFile : Text | LocalDir : Text | RepoPath : Text | Url : Text >
```

## API Update Graph

APIs form a directed update graph:

```
API Owner → Client Library → Application Consumers
```

```haskell
-- ApiUpdatePolicy
{ strategy : ApiUpdateStrategy
, allowBreaking : Bool
, requireTests : Bool
, consumerBatching : ConsumerBatching
, notes : Optional Text
}

-- ApiUpdateStrategy.dhall
< ClientFirst | ManualApproval | NoAutomation >

-- ApiDependencyRole.dhall
< Client | Consumer >

-- ConsumerBatching.dhall
< Sequential | Parallel >
```

## Configuration Specification

Packages declare runtime configuration requirements with source hints for tooling:

```haskell
-- ConfigItem
{ key : Text
, type : ConfigValueType
, required : Bool
, description : Optional Text
, sourceHint : Optional ConfigSourceHint
, example : Optional Text
}

-- ConfigValueType.dhall
< String | Integer | Boolean | Secret | Url
| FilePath | Duration | Json | Other : Text >

-- ConfigSourceHint.dhall
< EnvVar : Text | K8sSecret : Text | K8sConfigMap : Text
| Vault : Text | File : Text | Default : Text >
```

## Standards

Standard projects publish shared documentation and conventions. They have a scope and declare which project types and languages they apply to:

```haskell
-- StandardProject
{ name : Text
, scope : StandardScope
, description : Optional Text
, repo : Repo
, docs : List DocRef
, appliesTo :
    { types : List PackageType
    , languages : List Language
    }
}

-- StandardScope.dhall
< Organization | Domain | Platform | Language | Team | Other : Text >
```

Standards are declared, not inferred. Mori never assumes standards apply unless explicitly referenced.

## Mental Model

> `mori.dhall` is the **identity layer**. It declares what a project *is*, what it contains, and what agents should know. It does **not** declare what happens when events occur — that belongs in `mori.automation.dhall`.
