Mori makes your projects self-describing and queryable — so humans, agents, and automation all share the same structured understanding of what each project is, what it depends on, and how it connects to everything else.

## What is Mori?

Mori is a **typed project metadata system** for repositories. It describes *what a project is*, *what it depends on*, and *what agents should know about it*.

At its core, Mori provides two configuration files:

- **`mori.dhall`** — the **identity layer**: declares project metadata, packages, dependencies, APIs, agent hints, and documentation references using [Dhall](https://dhall-lang.org/), a typed configuration language
- **`mori.automation.dhall`** — the **automation layer**: declares event selectors and reactive behaviors triggered by VCS events

## Core Value Proposition

| Problem | Without Mori | With Mori |
|---------|--------------|-----------|
| Dependency paths | Hardcoded in each repo | Resolved via local registry |
| Documentation | Scattered, duplicated | Centralized in wrapper projects |
| Agent context | Manual prompt engineering | Structured, queryable metadata |
| Cross-repo automation | Ad-hoc scripts | Event-driven, policy-governed |

## Key Concepts

- **Schema-first** — Dhall files are authoritative; JSON is derived
- **Registry-first resolution** — dependencies are resolved by name, not hardcoded paths
- **Event-sourced** — all state changes are immutable events in MessageDB
- **Local-first** — works entirely offline on a single developer machine
- **Agent-aware** — metadata is designed to generate reliable AI agent context
