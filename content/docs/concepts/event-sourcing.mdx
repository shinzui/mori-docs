Mori uses event sourcing as its core persistence model:

- **Events are the source of truth** — all state is derived by folding events
- **MessageDB** provides the event store — a battle-tested PostgreSQL extension
- **Projections** (read models) are stored in PostgreSQL tables for fast queries
- **Subscriptions** process events and update projections

This architecture enables:

- Full audit trail of all changes
- Deterministic replay
- Horizontal scaling via consumer groups
- Same infrastructure for local and global registry (Phase 2)

## Why MessageDB Over SQLite

The original design considered SQLite for simplicity. MessageDB was chosen because:

| Concern | SQLite | MessageDB |
|---------|--------|-----------|
| Event storage | Custom schema | Purpose-built |
| Subscriptions | Manual implementation | Built-in |
| Idempotency | Manual implementation | Checkpoints |
| Horizontal scaling | Not supported | Consumer groups |
| Observability | Manual | OpenTelemetry integration |
| Code reuse | New code | Existing `message-db-hs` ecosystem |
| Global registry | Different implementation | Same infrastructure |

## Identity: TypeIDs

Mori uses **TypeIDs** for all entity identifiers:

```
repo_01h455vb4pex5vsknk084sn02q      # Repository
proj_01h455vb4pex5vsknk084sn02q      # Project
pkg_01h455vb4pex5vsknk084sn02q       # Package
```

### Repository ID

- Generated on `mori init`
- Stored in `mori.dhall` (or a local metadata file)
- Stable across renames and moves

### Project Namespace

Projects have a required namespace (organization):

```
@acme/payments-service
@acme/streamly-project
```

- Namespace does NOT have to match GitHub org
- Enables registry-style naming (`@org/project`)
- Required for all projects

## Stream Organization

### Entity Streams

Each aggregate has its own stream:

```
repository-{repo_typeid}
  └── VCS events, config observations

project-{namespace}:{name}
  └── Registration, updates

reaction-{event_typeid}:{reaction_name}
  └── Reaction lifecycle
```

### Category Streams

Subscriptions consume category streams:

```
repository    → All repository events
project       → All project/registry events
reaction      → All reaction events
```

### Stream Naming Convention

```
{category}-{entity_id}

Examples:
  repository-repo_01h455vb4pex5vsknk084sn02q
  project-@acme:payments-service
  reaction-evt_01h455vb4pex5vsknk084sn02q:notify-slack
```

## Event Types

### Repository Events (5 types)

Defined in `Mori.Modules.Repository.Domain.Event`. Top-level uses TaggedObject `"type"`/`"data"` encoding via `eventAesonOptions`; nested data types use `defaultOptions` (camelCase).

```haskell
data RepositoryEvent
  = ChangesetObserved !ChangesetObservedData
  | RefObserved !RefObservedData
  | MoriAutomationObserved !MoriAutomationObservedData
  | MoriConfigObserved !MoriConfigObservedData
  | RepositoryDayOpened !RepositoryDayOpenedData

data ChangesetObservedData = ChangesetObservedData
  { repoId      :: !RepoId
  , changesetId :: !ObjectId
  , treeId      :: !ObjectId
  , parents     :: ![ObjectId]
  , author      :: !PersonStamp
  , committer   :: !PersonStamp
  , message     :: !CommitMessage
  , refs        :: ![Text]
  , touchedPaths :: ![Text]        -- Files changed; used for automation matching
  , metadata    :: !(Map Text Text)
  }

data RefObservedData = RefObservedData
  { repoId  :: !RepoId
  , refName :: !Text
  , refKind :: !RefKind
  , target  :: !(Maybe ObjectId)   -- Nothing = deleted
  }

data MoriConfigObservedData = MoriConfigObservedData
  { repoId     :: !RepoId
  , configHash :: !Text
  }

data MoriAutomationObservedData = MoriAutomationObservedData
  { repoId         :: !RepoId
  , automationHash :: !Text
  , selectorCount  :: !Int
  , reactionCount  :: !Int
  }

data RepositoryDayOpenedData = RepositoryDayOpenedData
  { repoId        :: !RepoId
  , day           :: !Day
  , vcsType       :: !VcsType
  , repoPath      :: !Text
  , activatedAt   :: !UTCTime
  , lastChangeset :: !(Maybe ObjectId)
  , automationHash :: !(Maybe Text)
  , configHash    :: !(Maybe Text)
  }
```

## Projections

Projections are PostgreSQL tables updated by subscriptions.

### Registry Projection

```sql
-- mori.projects
CREATE TABLE mori.projects (
  id TEXT PRIMARY KEY,           -- TypeID
  namespace TEXT NOT NULL,
  name TEXT NOT NULL,
  project_type TEXT NOT NULL,
  path TEXT NOT NULL,
  config_hash TEXT,
  registered_at TIMESTAMPTZ NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL,
  message_global_position BIGINT NOT NULL,

  UNIQUE (namespace, name)
);

-- mori.packages
CREATE TABLE mori.packages (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES mori.projects(id),
  name TEXT NOT NULL,
  package_type TEXT NOT NULL,
  language TEXT NOT NULL,
  path TEXT,
  message_global_position BIGINT NOT NULL
);

-- mori.dependencies (lookup table for resolution)
CREATE TABLE mori.dependencies (
  name TEXT PRIMARY KEY,         -- Dependency name (e.g., "streamly")
  project_id TEXT NOT NULL REFERENCES mori.projects(id),
  package_path TEXT NOT NULL,    -- Resolved filesystem path
  message_global_position BIGINT NOT NULL
);

-- mori.bundles
CREATE TABLE mori.bundles (
  name TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES mori.projects(id),
  packages TEXT[] NOT NULL,      -- Package names in bundle
  primary_package TEXT NOT NULL,
  message_global_position BIGINT NOT NULL
);
```

### Repository Config Projection

```sql
-- mori.repository_configs
CREATE TABLE mori.repository_configs (
  repo_id TEXT PRIMARY KEY,
  config_hash TEXT NOT NULL,
  automation_hash TEXT,
  config_json JSONB NOT NULL,
  automation_json JSONB,
  updated_at TIMESTAMPTZ NOT NULL,
  message_global_position BIGINT NOT NULL
);
```

### Reaction History Projection

```sql
-- mori.reaction_history
CREATE TABLE mori.reaction_history (
  id TEXT PRIMARY KEY,
  triggering_event_id TEXT NOT NULL,
  reaction_name TEXT NOT NULL,
  status TEXT NOT NULL,          -- triggered, completed, failed
  started_at TIMESTAMPTZ NOT NULL,
  completed_at TIMESTAMPTZ,
  error TEXT,
  message_global_position BIGINT NOT NULL,

  -- Idempotency: prevent duplicate reactions
  UNIQUE (triggering_event_id, reaction_name)
);
```

### Projection Rebuild

If projections need rebuilding (schema change, corruption):

1. Truncate projection tables
2. Reset subscription checkpoint to position 0
3. Restart subscription — replays all events

## Subscriptions

All four subscriptions run concurrently inside `mori automate run`, sharing a single connection pool and using `message-db-checkpoint-store` for position tracking.

| Subscription | Category | Purpose |
|---|---|---|
| `mori-registry` | `project` | Updates registry projection tables |
| `mori-config-observation` | `repository` | Updates config projection, enables hot-reload |
| `mori-automation` | `repository` | Matches events against selectors, triggers reactions |
| `mori-reaction-executor` | `reaction` | Executes triggered reaction actions |

### Registry Subscription (`mori-registry`)

Subscribes to the `project` category. Updates registry projection tables (`projects`, `packages`, `dependencies`, `bundles`) from project events. Handles all 11 granular project event types with targeted updates and single-item deletes.

Defined in `Mori.Modules.Project.Subscription.RegistryHandler`.

### Config Observation Subscription (`mori-config-observation`)

Subscribes to the `repository` category. Updates the `repository_configs` projection table when `MoriConfigObserved` or `MoriAutomationObserved` events arrive. Enables IORef-based hot-reload of automation config.

Defined in `Mori.Modules.Repository.Subscription.ConfigObservationHandler`.

### Automation Subscription (`mori-automation`)

Subscribes to the `repository` category. Matches `ChangesetObserved` and `RefObserved` events against automation config selectors (glob patterns for paths, regex for branches/refs). When a match is found, triggers a reaction by writing a `ReactionTriggered` event.

Config is loaded via IORef and hot-reloaded when the config observation handler detects changes.

Defined in `Mori.Automation.Subscription.AutomationHandler`.

### Reaction Executor Subscription (`mori-reaction-executor`)

Subscribes to the `reaction` category. Executes triggered reactions:
- **RunCommand** — shell execution via `System.Process`
- **EmitEvent** — write event to a MessageDB stream
- **Notify** — HTTP webhook via curl
- **Schedule** — enqueue delayed action to PGMQ

Writes `ReactionCompleted` or `ReactionFailed` events and updates the `reaction_history` projection table.

Defined in `Mori.Automation.Subscription.ExecutorHandler`.

## Event Flow

```
VCS Event (git commit, jj operation)
   ↓
Normalize to canonical events
   ↓
Write to MessageDB (repository-{id} stream)
   ↓
Subscriptions process events:
   ├── mori-automation: match events → trigger reactions
   ├── mori-registry: update project/dependency projections
   └── mori-reaction-executor: execute triggered reactions
   ↓
Update projections (PostgreSQL tables)
   ↓
Emit effects (run commands, notify, emit new events)
```

## CLI Integration

### Write Path (via events)

```haskell
-- mori register --local
registerLocal :: MoriConfig -> Eff MoriEffects ()
registerLocal config = do
  projectId <- generateTypeId "proj"
  let event = ProjectRegistered
        { projectId = projectId
        , namespace = config ^. #project . #namespace
        , name = config ^. #project . #name
        , ...
        }
  writeMessage (projectStream config) event

-- mori automate ingest
ingestVcsEvents :: RepoId -> VcsAdapter -> Eff MoriEffects ()
ingestVcsEvents repoId adapter = do
  events <- adapter.getNewEvents
  forM_ events $ \evt ->
    writeMessage (repositoryStream repoId) evt
```

### Read Path (from projections)

```haskell
-- mori deps locate streamly
locateDependency :: Text -> Eff MoriEffects (Maybe DependencyInfo)
locateDependency name = do
  -- Query projection directly
  runQuery $
    select depTable
    & where_ (#name .== literal name)

-- mori agent context backend
getAgentContext :: Role -> Eff MoriEffects AgentContext
getAgentContext role = do
  project <- getCurrentProject
  deps <- resolveDependencies (project ^. #dependencies)
  standards <- resolveStandards (project ^. #standards)
  pure $ assembleContext role project deps standards
```

## Effect Stack

Defined in `Mori.Effects`:

```haskell
-- Read operations (event store + config)
type MoriReadEff es =
  ( MessageDb :> es
  , Reader StreamCategories :> es
  , IOE :> es
  )

-- Read + write operations
type MoriEff es =
  ( MoriReadEff es
  , Error WrongExpectedVersion :> es
  , Error StreamMessageParsingError :> es

  , Error SessionError :> es
```
